# Portfolio redesign / field notes

## Direction: evidence over effects
This portfolio uses an editorial "field notes" visual language: warm paper/ink palettes, one deliberate botanical accent, serif display type with a plain sans-serif body, narrow mono metadata, honest project rows and minimal motion. No floating service bubbles, glass panels, looping marquees, invented screenshots, simulated agents, inflated claims, ornamental progress bars or generic "AI gradient" treatments. The one deliberate exception is Aki (below): a real, clearly labelled AI assistant with a small floating launcher.

## Real workflows
1. A recruiter opens the home page, reads the job focus, jumps to Work, scans eight projects (the current shortlist), opens a demo and finds contact details.
2. A client finds a relevant operational project, checks the responsibilities/technology and reaches the working form or email fallback.
3. A keyboard user can reach every visible control in document order; no invisible sections remain mounted behind opacity.
4. A mobile visitor can open/close navigation, switch theme and fill the form without horizontal scrolling.
5. A visitor (18+) opens Aki, confirms the welcome step and asks about Jason's projects; if the AI is unavailable, built-in quick answers still work.

## Design decisions
- **Navigation:** stable sticky header with real hash anchors, skip link, visible mobile menu and native scrolling; no full-screen scroll traps. Deep links (e.g. `/#work`) use a one-time instant scroll after React mount, because the browser can try to resolve the hash before the dynamic DOM exists. Anchor offset comes from 84px `scroll-padding-top` only (no duplicate `scroll-margin-top`). The browser smoke asserts section starts immediately below the sticky header, including phone and tablet widths.
- **Work:** project entries, current work labels, and FuturoHub's grouped public website links are sourced from `src/data/portfolioData.js`; don't invent images or new metrics. Keep INNERCIRCLE° work labeled private and ongoing. Don't assume the same stack applies to every FuturoHub sample.
- **Process:** keep the interactive 5-step panel inspired by the supplied screenshot, but use it to demonstrate a workflow rather than pretend to have live autonomous agents.
- **Theme:** dark by default when the operating system prefers dark; user choice persists when storage is available. Light variant uses #1a6541 on #eeece3 (>5:1 contrast), replacing the previous lower-contrast accent.
- **Header CTA:** "Let's talk" opens WhatsApp (`wa.me`, prefilled message) in a new tab with `rel="noopener noreferrer"` and an aria-label that says so. The Contact section's email/phone links are unchanged.
- **Contact:** reuse `useContactForm` and `submitContactForm` (configured backend), preserve honeypot and rate limiting. Leave send-success confirmation visible until explicitly dismissed. Never invent a working backend when secrets are absent.
- **Motion:** different sections earn different treatments—Home: scroll-linked Field Notes parallax; Work: alternating horizontal project entry; About: opposing story/experience columns plus a toolkit rise; Process: scroll-linked, decorative timeline rule; Contact: right/left intro/sidebar and a rising form. A fixed 2px global progress line reflects reading position. Use the existing `motion/react` hooks (`useScroll`, `useTransform`, `useSpring`, `useReducedMotion`) and `whileInView`. Entrances replay in both scroll directions (they reset when leaving the viewport and animate again on re-entry); reduced motion shows no entrance transforms. No opacity-zero entrances: meaningful text and links stay visible on the first frame. No pinned horizontal panels, layout shifts, or scroll interception. No infinite loops in page motion; the only looping animations are Aki's small status pulse and typing dots, both disabled under reduced motion.
- **Aki (chat assistant):** bottom-right launcher drawn by `robot-heads` (brown, head only, no box) with a short two-line greeting bubble; the panel reveals bottom-right to upper-left and keeps one fixed height so the log scrolls instead of the panel growing. Chat-app layout: Aki left, visitor right, text name labels, no avatars, compact bubbles, typing dots before each reply, a single scroll region and thin scrollbars. The header shows a status dot (green "here to help", orange busy, red not connected); only the green dot pulses, and it stays still under reduced motion. No provider status in the footer. Tone is friendly-professional and grounded in `portfolioData.js`; Aki answers only from that data and says it doesn't know rather than guessing; the welcome step never calls the 18+ confirmation a verified age. Full privacy/terms live in `public/aki-legal.html`; the consent version must match the Worker's `CONSENT_VERSION`.
- **Aki architecture:** the browser only talks to the Cloudflare Worker in `worker/`; provider keys, Turnstile secret and rate limits live there. Gemini answers first for consenting visitors in eligible regions, Groq is the backup, local quick answers are the final fallback. Everything stays on free tiers with no payment method on any account.
- **Maintainability:** React 19, Vite 8, Lucide icons already installed. Packages are added only with owner approval, pinned exactly and audited. Approved so far: `robot-heads` (MIT, pinned 0.3.0, audited: no network, storage or eval; draws Aki's launcher) and `wrangler` (pinned, a dev dependency of `worker/` only, never shipped to visitors). No external fonts, images or tracking. The only third-party script is Cloudflare Turnstile, loaded when a visitor first sends Aki a message, for bot protection; Aki's limiter stores only a keyed hash of the IP address prefix, never the raw address. The title is AI & Full-Stack Engineer; actual CV responsibilities have priority over generic AI claims. INNERCIRCLE° is part-time, FuturoHub freelance (no guessed start date), and the existing résumé PDF remains the only public CV link. - [ ] Every anchor points to a visible section; directly opening `/#work`, `/#about`, `/#process`, and `/#contact` lands on that section; Escape/menu closing, Tab order and focus indicators are usable.
- [ ] Text and accent remain legible in dark and light themes.
- [ ] At desktop and mobile widths, verify each distinct Home/Work/About/Process/Contact scroll effect and the global reading indicator. Scroll up and down to confirm entrances reset on leaving the viewport and animate again on re-entry from either direction. Project links must remain visible before animation frames complete.
- [ ] With reduced motion enabled, verify no entrance transforms or parallax, no fixed reading progress bar, and a static Process rule. Check motion does not impact keyboard focus or natural anchor scrolling.
- [ ] Chrome DevTools CI checks all five sections at every viewport in the matrix, mobile-menu Escape/focus and theme toggle, 1440/768/390px deep links, and reduced-motion behavior. DevTools connects only to the spawned Chrome instance via a dynamic port and matched WebSocket ID. Static images cannot verify animation smoothness.
- [ ] Form validation, rate-limits, failure fallback and successful submissions behave with the *actual* deployment backend.
- [ ] All public website links, including FuturoHub, El Mejor, Cup Section and samples 01–06, open as expected; private work is labeled; no extra portfolio claims.
- [ ] Current CV positioning, part-time versus freelance arrangements, and the unchanged PDF destination are verified.
- [ ] Aki: welcome gate requires the 18+ box; chat panel keeps its height as messages arrive; typing dots show before replies; quick answers work when the Worker is unreachable; Privacy and Terms links open `aki-legal.html`; Clear removes the conversation; keyboard and screen-reader status announcements work; layout fits at 320px in both themes.
- [ ] Aki rollout: Worker deployed with its five secrets, Turnstile widget bound to the live hostname, `GEMINI_ALLOWED_COUNTRIES` and `GEMINI_DAILY_CAP` reviewed, and no payment method on Cloudflare, Groq or the Google project.
- [ ] GitHub Actions installs dependencies, lints **changed JS/JSX**, runs the Aki Worker tests (no real provider calls) and builds the production bundle.
- [ ] Human approves the redesign and checks the published site after merge.

The GitHub Actions check is not a substitute for a browser, screen reader, or live-form test.
