# Source and adaptations

This workspace adapts [RinDig's Interpretable Context Methodology](https://github.com/RinDig/Interpretable-Context-Methodology/tree/02ba5d85c7871b75c7c702a2d8da6524723d53d4) at commit `02ba5d85c7871b75c7c702a2d8da6524723d53d4`, especially its [core conventions](https://github.com/RinDig/Interpretable-Context-Methodology/blob/02ba5d85c7871b75c7c702a2d8da6524723d53d4/_core/CONVENTIONS.md) and [workspace builder](https://github.com/RinDig/Interpretable-Context-Methodology/tree/02ba5d85c7871b75c7c702a2d8da6524723d53d4/workspaces/workspace-builder). The upstream MIT notice is preserved in [LICENSE](../LICENSE). ICM's file hierarchy, selective context loading, stage contracts, and editable handoffs are the inspiration; the portfolio-specific text, stages, and authority here are adaptations.

The entry points `AGENTS.md`, `CLAUDE.md`, and `CONTEXT.md` route both Codex and Claude to the same context. The setup profile begins with already confirmed choices, so setup should surface only unresolved decisions. Run status requires metadata and evidence, because a present output file may still be a draft or stale. Checkpoints produce reviewable artifacts and ask for human steering only when a consequential decision is unresolved.

This is a documentation adaptation. It does not run the upstream workspace builder or copy its runtime, scripts, examples, or assumption that every stage requires a pause. Its stage outputs are Markdown instructions and records; subsequent code changes remain subject to the repository's development and release rules.

The demo extension adds an alias-only [catalog](../shared/demo-catalog.md), a [public/private evidence and build boundary](../shared/demo-boundary.md), and a [release checklist](demo-release-checklist.md). These are portfolio-specific safety and presentation rules, not copied private-project documentation. Exact private source mappings, revisions, and inspection notes belong to the operator's private context, not to this public adaptation.
