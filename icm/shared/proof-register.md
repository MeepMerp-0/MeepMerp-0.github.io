# Public proof register

## INNERCIRCLE

The current [public portfolio record](../../src/data/portfolioData.js) presents INNERCIRCLE° at a high level as in-progress real estate operations and agentic AI work. Its existing public summary covers the operations platform, general technology and workflow categories, scoped API access, human approval, role-based access, and audit trails. Use **only that existing high-level public summary** in new portfolio copy; paraphrase within the same disclosure boundary. Do not add internal screenshots, diagrams, metrics, private repository information, access details, architecture specifics, or new outcome claims. A case study can explain role and broad problem only to the extent already public. Ask for explicit disclosure approval before expanding it.

## Aki

Aki is an on-site assistant and a public portfolio project. The [project record](../../src/data/portfolioData.js) and [public notice](../../public/aki-legal.html) are starting evidence for visitor-facing claims; the actual UI, Worker, and tests are required to verify current behavior before changing it. Do not turn configuration caps, listed providers, or a successful build into claims of live availability, cost guarantee, privacy compliance, or end-to-end provider testing.

Keep the original robot's assets, appearance, materials/colors, proportions, animations, and launcher unchanged. Permit only scoped chat-panel presentation, responsive geometry, existing theme binding, and necessary minimal presentational markup in an authorized redesign. Preserve copy, disclosures, semantics, event wiring, knowledge/prompts, conversation/streaming/request behavior, consent/privacy/session/region/storage, providers/quotas, voice review-before-explicit-send, accessibility, and Worker/services/configuration. No separate canned walkthrough, simulated voice demo, duplicate assistant, or replacement mock is authorized. Role authority in [model routing](model-routing.md#architecture-security-and-final-authority) does not expand this scope. Use before/after robot and functional evidence plus an allowlist for intentional chat styling changes.

## Evidence rules

- Label a statement **confirmed by user**, **verified in repository**, **observed in test/browser**, **proposal**, or **unverified**. Cite a public source path and public revision, or record a safe test artifact and date. For private demo sources, use aliases and safe evidence IDs in public records; hold exact provenance privately under the [evidence tiers](demo-boundary.md#public-and-private-evidence).
- Do not invent employers, roles, dates, availability, metrics, testimonials, project outcomes, or permission to disclose private work. A public record is the disclosure ceiling, not proof that an external system behaves as described today.
- Inspect shared consumers when copy changes: [portfolio data](../../src/data/portfolioData.js), [Aki answers](../../src/data/akiFaq.js), [Worker experience](../../worker/src/experience.js), [Worker knowledge](../../worker/src/knowledge.js), and [SEO metadata](../../index.html). For this rework, Aki copy/knowledge/prompts and Worker/runtime behavior are protected. Update authorized portfolio/SEO surfaces without changing Aki's consumed values; record a conflict or required synchronization as a separate task rather than automatically editing protected surfaces.
- Mark unexercised behavior `NOT TESTED` with a reason. Report exact checks and limitations under the [run contract](run-contract.md#artifact-metadata).
